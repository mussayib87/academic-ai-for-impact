# Local LLM

`ai/llm/provider.py` defines a structured `InterventionContext` and provider protocol. `LocalLLMProvider` sends that evidence to a separately installed Ollama server. Configure `LLM_PROVIDER=ollama` and `LLM_MODEL_NAME=ollama:<model>` after installing and pulling a local model. Ollama remains the default provider.

Optional Gemini generation is selected with `LLM_PROVIDER=gemini`, `GEMINI_MODEL_NAME=<model>`, and a secret supplied through `GEMINI_API_KEY`. Keys are never stored in source or required for tests. If the Gemini key is missing, the configured Ollama provider remains available; when Ollama is not configured, the explicit development template remains the fallback.

When `LLM_MODEL_NAME` does not select Ollama, the system uses `DevelopmentDraftProvider`. This deterministic template is labeled “not generated by a language model”; it is a development fallback, not an LLM. The UI identifies the provider.

Risk is always produced by the trained classifier. The provider receives risk probabilities, SHAP factors, momentum, attendance, assessment, assignment engagement, retrieved sources, and available subject-mark context only to draft supportive text. Subject marks are context, not current model predictors; prompts prohibit attribution of global risk/SHAP to a subject, diagnosis, invented policy, unsupported claims, and automatic action. Faculty must review/edit and explicitly approve; approval stores the intervention and creates an in-app student notification. No external message is sent.
